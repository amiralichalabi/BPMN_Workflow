# استودیوی BPMN

بوم طراحی فرایند با علامت‌های استاندارد **BPMN 2.0** (همان خانواده‌ی Bizagi / Visual Paradigm) + **نسخه‌بندی شبیه Git** + **پوستر نمایشی**.
هیچ منطق کسب‌وکاری، کارتابل، فرم یا موتور اجرا ندارد؛ فقط طراحی، ثبت تغییرات و نمایش.

## اجرا (ساده‌ترین راه: GitHub Codespaces)
1. این پوشه را در یک ریپوی GitHub بگذارید → **Code ▸ Codespaces ▸ Create**.
2. چند دقیقه صبر کنید (ساخت ایمیج). پورت **8080** باز می‌شود.
3. رمز اولیه‌ی مدیر: در ترمینال `docker compose logs studio | grep -i "INITIAL ADMIN"` (نام کاربری `admin`).
   یا قبل از اجرا فایل `.env` را با `ADMIN_PASSWORD=...` (حداقل ۱۰ نویسه) بسازید.

روی سرور یا سیستم خودتان:
```bash
cp .env.example .env      # ADMIN_PASSWORD را پر کنید
docker compose up -d --build
# http://localhost:8080
```
پشت پروکسی HTTPS (Nginx/Caddy/Cloudflare) حتماً `BEHIND_PROXY=true` بگذارید تا کوکی `Secure` شود.

## قابلیت‌ها
- **بوم BPMN 2.0 کامل** (bpmn-js): رویدادها، فعالیت‌ها، دروازه‌ها، Pool/Lane، زیرفرایند، یادداشت و …؛ خروجی `.bpmn` / SVG / PNG و ورود فایل `.bpmn` از Bizagi و Visual Paradigm.
- **نسخه‌بندی ملموس**
  - «ثبت نسخه جدید» همیشه قبل از ذخیره، فهرست دقیق تغییرات را نشان می‌دهد (افزوده / حذف / تغییر / جابه‌جایی) و پیام نسخه می‌خواهد.
  - تاریخچه به‌صورت خط زمانی با نشان‌های `+۳ −۱ ~۲ ↔۴`، نویسنده، زمان شمسی و کد هش.
  - **مقایسه تصویری** دو نسخه کنار هم: قرمز = حذف، سبز = افزوده، نارنجی = تغییر، آبی خط‌چین = جابه‌جا (با زوم/اسکرول هماهنگ).
  - برچسب‌گذاری نسخه‌ها، مشاهده‌ی نسخه‌های قدیمی (فقط‌خواندنی) و **بازگردانی** (نسخه‌ی جدید می‌سازد؛ هیچ‌چیز پاک نمی‌شود).
  - نسخه‌ها در پایگاه‌داده با تریگر **غیرقابل ویرایش و حذف** هستند؛ ذخیره‌ی هم‌زمان دو نفر با هشدار تداخل (409) مدیریت می‌شود.
- **پوستر**: صفحه‌ی نمایشی با عنوان، نسخه، تاریخ، راهنمای علامت‌های BPMN، چاپ A3 / PDF، SVG، PNG و تمام‌صفحه. پیوند اشتراک‌گذاری فقط‌خواندنی (قابل لغو) برای نمایش بدون ورود.
- نقش‌ها: **بیننده** (فقط ببیند)، **طراح** (ویرایش و نسخه‌گذاری)، **مدیر** (کاربران و ممیزی).

## امنیت
| مورد | پیاده‌سازی |
|---|---|
| رمز عبور | PBKDF2-SHA256 با ۶۰۰ هزار تکرار؛ حداقل ۱۰ نویسه؛ رمز پیش‌فرض ثابت وجود ندارد |
| ورود | قفل ۱۰ دقیقه‌ای پس از ۵ تلاش ناموفق + محدودیت نرخ + زمان پاسخ یکسان برای کاربر ناموجود |
| نشست | کوکی HttpOnly + SameSite=Strict (+Secure پشت HTTPS)، انقضای ۸ ساعته؛ غیرفعال‌شدن کاربر ظرف چند ثانیه اعمال می‌شود |
| CSRF | هدر سفارشی `X-Studio` + بررسی Origin علاوه بر SameSite |
| XSS | CSP سخت‌گیرانه (`script-src 'self'`)، همه‌ی متن‌ها با `textContent`، فایل‌های editor از خود سرور (بدون CDN) |
| XXE / فایل مخرب | پارس XML با DTD ممنوع، سقف ۵ مگابایت، اعتبارسنجی ساختار BPMN |
| دسترسی | پیش‌فرض «ورود لازم است» برای همه‌ی endpointها؛ نقش‌ها در سمت سرور کنترل می‌شوند |
| ممیزی | جدول Append-only با تریگر (ورود، ذخیره، بازگردانی، اشتراک، تغییر کاربران، با IP و شناسه‌ی رهگیری) |
| کانتینر | کاربر غیر root، فایل‌سیستم read-only، `cap_drop: ALL`، `no-new-privileges` |

## سرعت
- نسخه‌ی قبلی (موتور Java + PostgreSQL) حذف شد: اینجا فقط یک کانتینر سبک .NET با SQLite در حالت WAL است (راه‌اندازی در چند ثانیه، حافظه‌ی کم).
- لیست نسخه‌ها هرگز XML را نمی‌خواند؛ XML فقط هنگام باز کردن یک نسخه بارگذاری می‌شود.
- فشرده‌سازی پاسخ‌ها، کش یک‌ساله‌ی فایل‌های ثابت editor (مسیر نسخه‌دار) و ETag برای فایل‌های برنامه.

## تست سریع
```bash
ADMIN_PASSWORD=... bash scripts/smoke.sh http://localhost:8080
```
تست دستی پیشنهادی: ۱) دو نسخه بسازید و «نمایش تغییرات» را بزنید. ۲) در دو مرورگر هم‌زمان یک نمودار را ویرایش و ذخیره کنید (باید تداخل ببینید).
۳) در `sqlite3 /data/studio.db "DELETE FROM DiagramVersions"` خطای immutable می‌گیرید. ۴) کاربر را غیرفعال کنید؛ نشست او بسته می‌شود.

## محدودیت‌ها و گام‌های بعدی
- ورود فعلاً با کاربر/رمز داخلی است؛ برای سازمان: OIDC (Keycloak / Azure AD).
- دسترسی در سطح هر نمودار (ACL) و PostgreSQL برای چندسرور هنوز نیست. ساختار جداول با `EnsureCreated` ساخته می‌شود؛ پیش از تغییر شِما، Migration اضافه کنید.
- Pool/Lane و DMN: ویرایش و نمایش BPMN کامل است، ولی دیف عنصر به‌صورت «بر اساس شناسه‌ی عنصر» است (جابه‌جایی مسیرها گزارش نمی‌شود).
