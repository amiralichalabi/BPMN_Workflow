# استودیوی BPMN

بوم طراحی فرایند با علامت‌های استاندارد **BPMN 2.0** + **نسخه‌بندی شبیه Git** + **پوستر نمایشی**.
بدون منطق کسب‌وکار: فقط طراحی، ثبت تغییرات و نمایش.

## اجرا (SQL Server)
برنامه با **SQL Server** کار می‌کند؛ جدول‌ها در اولین اجرا خودکار ساخته می‌شوند و کلیدهای رمزنگاری نشست هم داخل همان دیتابیس نگه‌داری می‌شوند (برنامه خودش هیچ فایلی روی دیسک نمی‌نویسد).

**۱) تست سریع با کانتینر آزمایشی SQL Server (Codespaces یا سیستم خودتان):**
```bash
cp .env.example .env      # SQL_PASSWORD و ADMIN_PASSWORD را پر کنید
docker compose up -d --build   # http://localhost:8080
```
رمز مدیر اگر خالی بماند: `docker compose logs studio | grep -i "INITIAL ADMIN"`.

**۲) روی SQL Server خودتان (پیشنهادی برای استفاده‌ی واقعی):**
1. یک دیتابیس خالی (مثلاً `BpmnStudio`) و یک لاگین با مجوز `db_owner` (فقط برای اولین اجرا، چون جدول و تریگر می‌سازد) یا مجوزهای ساخت جدول.
2. در `.env`: `CONNECTION_STRING=Server=...;Database=BpmnStudio;User Id=...;Password=...;Encrypt=True;TrustServerCertificate=False`
3. بالا آوردن: `docker compose -f docker-compose.prod.yml up -d --build` (این فایل کانتینر SQL Server ندارد و پورت را فقط روی localhost باز می‌کند؛ HTTPS را Caddy/Nginx بدهد)
4. بعد از ساخت جدول‌ها، مجوز لاگین برنامه را به `db_datareader` + `db_datawriter` کم کنید (حداقل دسترسی).
> نسخه‌ها و ممیزی با تریگر داخل SQL Server غیرقابل ویرایش/حذف‌اند؛ مالک دیتابیس همچنان می‌تواند تریگر را بردارد، پس مجوز ALTER را به لاگین برنامه ندهید.
> ساختار جدول‌ها با `EnsureCreated` ساخته می‌شود؛ برای تغییر شِما در نسخه‌های بعدی باید Migration اضافه شود.

## صفحه‌ی اول
جدول کامل گردش‌کارها: سامانه، نام، عامل، نقش، ثبت‌کننده، تاریخ ثبت، آخرین تغییر، نسخه. جست‌وجوی هم‌زمان در همه‌ی ستون‌ها، فیلتر سامانه، مرتب‌سازی با کلیک روی عنوان ستون، باز شدن ردیف برای جزئیات و منوی همبرگری ☰ برای تاریخچه‌ی نسخه‌های هر گردش کار.
در «گردش کار جدید» فیلدهای سامانه، نام، عامل، نقش و توضیحات گرفته می‌شود؛ تاریخ و ثبت‌کننده را سیستم خودکار ثبت می‌کند.

## بوم
- تمام‌صفحه، با شبکه (نمایش + چسبیدن)، تراز (چپ/وسط/راست/بالا/میانه/پایین)، توزیع افقی/عمودی، زوم و Undo/Redo.
- **جعبه‌ابزار بازشونده**: رویدادها، فعالیت‌ها، زیرفرایند، دروازه‌ها، داده/یادداشت/استخر، و **سرتیتر** و **تصویر** (داخل فایل BPMN ذخیره می‌شوند).
- رنگ پیش‌فرض بر اساس نوع: فعالیت آبی، شروع سبز، میانی زرد، پایان قرمز، دروازه زرد؛ از ⚙ تنظیمات ▸ «سبک نمودارها» برای همه قابل تغییر است (رنگ‌ها و فونت). رنگ دستی هر عنصر از نوار ابزار بوم.
- زیرفرایند بدون دایره‌ی داخلی ساخته می‌شود.

## نسخه‌بندی
ثبت نسخه با پیش‌نمایش دقیق تغییرات و پیام الزامی؛ منوی ☰ برای جابه‌جایی بین نسخه‌ها؛ مقایسه‌ی تصویری دو نسخه (قرمز حذف، سبز افزوده، نارنجی تغییر، آبی جابه‌جا)؛ برچسب؛ بازگردانی بدون حذف تاریخچه؛ نسخه‌ها در دیتابیس غیرقابل ویرایش/حذف؛ هشدار تداخل ذخیره‌ی هم‌زمان.

## ورود و خروج فایل (Bizagi و ابزارهای دیگر)
- **ورود:** `.bpmn`، `.xml` و `.bpm` (اگر `.bpm` یک فایل فشرده باشد، داخلش دنبال BPMN استاندارد می‌گردد).
- **خروج:** `.bpmn`، `.xml`، SVG، PNG و PDF (از پوستر).
- نکته: `.bpm` قالب اختصاصی Bizagi است و نوشتن آن ممکن نیست. برای هم‌گام‌سازی: در Bizagi از *File ▸ Export ▸ BPMN 2.0* فایل `.bpmn` بگیرید، اینجا «ورود فایل» بزنید و تغییرات را ببینید/ثبت کنید؛ برای برگشت، از اینجا `.bpmn` بگیرید و در Bizagi Import کنید. سرتیتر و تصویر در ابزارهای دیگر به‌صورت «یادداشت» دیده می‌شوند.

## پوستر و استفاده روی یک سایت
- پوستر: عنوان، سامانه، نسخه، تاریخ، راهنمای علامت‌های BPMN، چاپ A3/PDF، SVG، PNG.
- **سایت مستقل:** روی یک زیردامنه (مثلاً `bpmn.company.com`) با HTTPS و `BEHIND_PROXY=true` اجرا کنید.
- **نمایش داخل سایت/پورتال موجود:** در «اشتراک‌گذاری» پیوند فقط‌خواندنی بسازید و کد `<iframe>` را در صفحه بگذارید. برای اجازه‌ی تعبیه، `EMBED_ORIGINS=https://site-you.com` را تنظیم کنید (فقط صفحه‌ی پوستر قابل تعبیه است).
- اجرا زیر مسیر فرعی (مثل `/bpmn/`) پشتیبانی نمی‌شود؛ زیردامنه پیشنهاد می‌شود.

## امنیت (خلاصه)
PBKDF2 برای رمز، قفل پس از ۵ تلاش ناموفق، کوکی HttpOnly/SameSite=Strict، هدر CSRF + بررسی Origin، CSP سخت‌گیرانه (بدون CDN)، پارس XML بدون DTD، سقف حجم، ممیزی Append-only، نسخه‌های غیرقابل ویرایش، کانتینر غیر root با فایل‌سیستم read-only. تصاویر فقط با قالب data:image (png/jpeg/gif/webp) نمایش داده می‌شوند.

## تست سریع
`ADMIN_PASSWORD=... bash scripts/smoke.sh http://localhost:8080`

## محدودیت‌ها
ورود فعلاً داخلی است (برای سازمان: OIDC). دسترسی در سطح هر نمودار و Migration دیتابیس هنوز نیست. کد در محیط من کامپایل نشده؛ اولین اجرای CI خطاهای احتمالی را نشان می‌دهد.
